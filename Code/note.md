Q1：如何给出综合评分

解决：预留需要查询的敏感属性接口，对于类似[属性A,属性B]的查询，通过交集属性组合，利用上面的组间差异量化结果来给出计算。

Q2：查询和数据量的不对等性。

描述：对于敏感属性的交集，如果允许任意属性组合直接评估，会引发“稀疏性灾难”，超过八成的组别是数据量稀疏而无效的；对于条目较多的数据集，保存全部中间结果会产生较大规模的文件（这个不着急解决）；

解决：设置最大属性组合数。

Q3：二分类任务上流程，仓库架构？

解决：config配置文件（针对每个数据集），分离infer和eval阶段，中间结果存储；流程为“生成预测结果->合并结果->调用evaluator评估->生成指标评分”；仓库架构类比opencompass，区分各个接口和核心代码实现部分
